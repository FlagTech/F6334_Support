# 結構化會議記錄

將零散的會議文字整理成可閱讀、可追蹤的標準會議記錄，另存為新的 Markdown 檔並交付。忠實保留原始資訊，不把推測包裝成事實，也不修改或覆寫原始素材。

## 工作流程

1. 取得來源內容。
   - 使用使用者貼上的文字，或讀取指定的 `.txt`、`.md` 檔案。
   - 不修改原始素材。
   - 遇到錄音或影片時，請使用者先提供逐字稿或可讀文字；不要聲稱已完成轉錄。
   - 若沒有足以辨識會議內容的素材，請使用者補充來源，不要產生空泛記錄。

2. 決定輸出語言。
   - 沿用來源的主要語言。
   - 中文內容使用繁體中文、台灣用語與全形標點。
   - 使用者指定語言或格式時，以明確指示為準。

3. 建立事實清單後再撰寫。
   - 擷取會議日期、時間、地點或形式、主題、出席者、缺席者、主持人與記錄者。
   - 擷取討論進度、明確決策、暫定方案、建議、行動項目、風險、阻塞、指標、門檻、下次會議與會後補充。
   - 為每個行動項目分別確認事項、負責人、期限、狀態與相依條件。
   - 合併語意相同的重複內容，但保留後續修正與狀態變化。

4. 保守判定資訊。
   - 只把明確同意、確認或決定的內容標為「已決議」。
   - 把帶有「暫定、預計、如果、可能」等條件的內容標為「暫定」或「有條件」。
   - 把個人意見、提案或成本估算標為「建議」或「估算」，不要寫成核准事項。
   - 把討論中斷、意見分歧或尚未決定的內容列入「待確認事項」。
   - 缺少必要的負責人、期限或結論時，明確填寫「待確認」；不要從職稱、上下文或常識推定。
   - 資訊互相衝突時並列所有版本並標示衝突，不要擅自選擇。
   - 只有在會議日期已知且相對日期可唯一解析時，才補上絕對日期，格式為「YYYY/MM/DD（原文：明天）」；否則保留原文並標示待確認。
   - 保留數字、日期、金額、比例、門檻、更新頻率與觸發條件。
   - 會後補充只標示原文明確提供的來源或發言者；若未明示來源，不要因內容提及某個人或單位就推定是該方提供。

5. 依照 [references/meeting-record-format.md](references/meeting-record-format.md) 產出完整記錄。
   - 保留範本中的所有主要章節。
   - 整個章節沒有相關資訊時填寫「原始資料未提及」。
   - 不逐段重述逐字稿；只保留理解決策、分歧與後續行動所需的脈絡。
   - 非中文輸出時，翻譯標題與欄位，但維持相同結構和判定語意。

6. 決定儲存位置與檔名。
   - 使用者指定輸出路徑或檔名時，優先採用其指示。
   - 來源是本機檔案且未指定位置時，將結果存放在來源檔案的同一個資料夾。
   - 來源是貼上的文字且未指定位置時，將結果存放在目前工作區。
   - 本機來源檔案的預設檔名為 `<原始檔名（不含副檔名）>_結構化會議記錄.md`。
   - 貼上文字的預設檔名依序採用：`<會議日期>_<會議主題>_會議記錄.md`、`<會議主題>_會議記錄.md`、`結構化會議記錄_<目前日期>.md`。會議日期使用 `YYYY-MM-DD`。
   - 移除檔名中的 `<>:"/\|?*`，並移除檔名結尾的空白與句點；檔名應簡短且能辨識內容。
   - 絕不覆寫原始素材或任何既有檔案。若目標檔名已存在，自動依序加上 `_2`、`_3` 等編號，不要求使用者再次選擇。

7. 另存並輸出。
   - 將完成的完整記錄另存為 UTF-8 編碼的 `.md` 檔。
   - 寫入後確認檔案存在、可讀，且內容與完成的記錄一致。
   - 確認原始素材仍存在且未被修改。
   - 成功後，在回覆中提供簡短完成訊息與可點擊的本機檔案連結；除非使用者明確要求預覽或貼出全文，否則不要在對話中重複完整記錄。
   - 若指定位置無法寫入，改在目前工作區用安全的新檔名嘗試一次，並告知實際儲存位置。
   - 若仍無法建立檔案，清楚說明阻礙，並在對話中提供完整 Markdown 記錄作為備援。
   - 若使用者明確要求 Markdown 以外的格式，使用適合該格式的技能或工具產出，但仍須保留原始素材並避免覆寫既有檔案。

## 交付前檢查

- 確認每項決策的狀態與原始語氣一致。
- 確認每項行動的負責人和期限都有來源，否則標為「待確認」。
- 確認風險、門檻、條件與相依關係沒有被省略。
- 確認衝突與未決事項沒有被誤寫成結論。
- 確認沒有加入來源中不存在的人名、日期、數字、承諾或因果關係。
- 確認會後補充與修正沒有被當成原會議當下已知資訊。
- 確認輸出檔案是新檔、可讀，且檔案連結指向實際儲存的結果。
- 確認原始素材沒有被修改或覆寫。
